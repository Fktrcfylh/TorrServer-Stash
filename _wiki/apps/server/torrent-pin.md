# Torrent pin

**App:** server
**Status:** stable — Phases 1–6 of 6 complete (specs/torrent-predownload): pin model + API; on disk storage the pin set (`all` or `next` window from the anchor) keeps every piece of the torrent, downloads the wanted pieces in background and blocks timeout unload until they are complete; starting an episode moves the anchor and deletes watched episodes; `rem`/`off` (previously pinned only) delete the data dir, drop/timeout/`RemoveCacheOnDrop`/`cleanCache` keep pinned data; unfinished `all`/`next` pins resumed at start, after settings reload and every minute; status JSON per-file `pinned`/`completed`/`downloaded` + `pin_progress`/`pin_error`; persisted downloaded ids; free-space pause/resume; web UI (Phase 6)
**Last reviewed:** 2026-09-14 (staged Phases 1–6 diff on `215f6fca`)

## Summary
A torrent can be pinned for predownload: mode `all` (whole torrent minus watched episodes) or `next` (anchor episode K and the next N episodes). The pin is stored on the DB row, mirrored on the in-memory `Torrent`, exposed in status JSON and set via `POST /torrents` `action:"pin"`. For a loaded torrent on `UseDisk`, `applyPin` computes an immutable pin set `{want, drop}` from (mode, N, anchor, file layout) and pushes it to its `torrstor.Cache` (`SetPin`): no piece of a pinned torrent is evicted, wanted incomplete pieces get priority `Normal` with no reader, and the torrent stays loaded (`expired()` false) until every wanted piece is complete. Before pushing, `applyPin` checks the free space of `TorrentsSavePath`; short of missing bytes + 1 GiB → empty want set (paused, `pin_error:"no_space"`). A GET stream of an episode of a pinned torrent makes it the anchor (persisted async), and pieces lying only in episodes before the anchor are deleted. Every second the ids of fully downloaded files are recorded (`PinDownloaded`); the resume loop skips pins whose target files are all downloaded. `TorrentsSavePath/<hash>` is deleted only by `rem` or by `off` on a previously pinned torrent; pinned rows keep their data on every other unload/cleanup path.

"Pinned" per path:
| Path | Predicate |
|---|---|
| Eviction (`getRemPieces`, `removePiece`) | `Cache.pin != nil` (`isKept`) — every piece of the torrent, paused too |
| Background priority `Normal`, `PinPending` → `expired()` | `isWanted(id)` = `want[id]` (paused: none) |
| Piece deletion (`dropPieces`) | `drop[id] && !want[id]`, file has no reader, piece has data |
| Status `pinned` (per file) | `pinTargets` target: `next` with episodes → episodes K..K+N; `all` or no episodes → every file except episodes before K |
| `downloaded` source | loaded: mirror `PinDownloaded`; stub: row `PinDownloaded` |
| Downloaded ids maintenance | mirror mode `all`/`next`, loaded with info, `UseDisk`, `!ReadOnly` |
| Keep data dir on close / `cleanCache` | DB row `PinMode != ""` (any mode) |
| Resume loop | DB row `PinMode` `all` or `next` **and not `pinFinished`** (every target with `length > 0` in `PinDownloaded`, `Data` has a TorrServer file list, `TorrentsSavePath/<hash>` exists) |
| Free-space pause | mirror mode `all`/`next`, `UseDisk`, info, free known and `< required + 1 GiB`, `required > 0` |
| Anchor move | mirror `PinMode` `all` or `next` |
| `off` deletes dir | DB row or loaded mirror pinned before the call (C2) |

## Flow — `POST /torrents {"action":"pin","hash","pin_mode","pin_next"?}`
Handler checks, in order (`server/web/api/torrents.go:194-225`):
1. `hash` empty → 400 (`:195-198`).
2. `set.ReadOnly` → 403 `Read-only mode` (`:199-202`).
3. `pin_mode` not `off|all|next` (absent included) → 400 (`:203-206`).
4. `pin_next` present and `< 0` → 400 (`:207-210`).
5. mode `all|next` and `!BTsets.UseDisk` → 400 `pin requires disk storage (UseDisk)` (`:211-214`). `off` passes.
6. `next = pin_next` or `BTsets.DefaultPinNext` (`:215-218`).
7. `torr.SetTorrentPin` nil → 404 `torrent not found` (`:219-223`); else 200 `tor.Status()` (`:224`).

`torr.SetTorrentPin` (`server/torr/apihelper.go:183-230`):
1. ReadOnly → log, nil (`:184-187`). Log line (`:188`) prints mode/N before normalisation.
2. `off` → `mode=""`, `next=0` (`:189-192`).
3. `bts.GetTorrent(hash)` (loaded only, never starts a load) (`:194`); `wasPinned = sets.IsTorrentPinned(hash)` **before** the write (`:196`); `saved := settings.SetTorrentPin` (`:197`, off also clears the row's `PinDownloaded`); `off` → `pinNoSpaceSet(hash, false)` for loaded and not loaded (`:198-200`).
4. Not loaded: row missing → nil (`:202-204`); `mode == "" && wasPinned` → `removeTorrentDir(hashHex)` immediately (`:205-207`); return fresh `GetTorrentDB` copy (`:208`).
5. Loaded: under `muTorrent` `wasPinned ||= PinMode != ""`, mirror mode/N, `off` → mirror `PinDownloaded = nil` (`:210-217`); `applyPin()` (`:218`). No row → `AddTorrentDB(torr)` then `settings.SetTorrentPin` again (`:219-224`).
6. `mode == "" && wasPinned` + `torr.closed != nil` + `UseDisk` + hash not empty/`/` → `go removeTorrentDirAfterClose(torr, hash, <path computed now>)` (`:226-228`). Returns loaded torrent.

`settings.SetTorrentPin` (`server/settings/torrent.go:65-84`) / `SetTorrentPinAnchor` (`:87-102`) / `SetTorrentPinDownloaded` (`:106-123`): under `mu`, read row, set mode/N (off: + `PinDownloaded = nil`) resp. anchor resp. downloaded ids only, marshal, `tdb.Set` that row; false if row missing (downloaded: or `PinMode == ""`) or marshal error.

## Flow — window calculation (`pinPieces`, `server/torr/pin.go:128-191`)
Pure function of `(files []pinFile in id order, pieceLength, pieceCount, mode, next, anchor)`.
1. Mode not `all`/`next`, or `pieceLength <= 0` → `nil, nil` (unpinned) (`:129-131`).
2. File piece range = half-open `[offset/pl, ceil((offset+length)/pl))` clamped to `pieceCount`; `length <= 0` → no pieces (`:136-149`).
3. Episodes = files with `utils.IsVideoFile && !utils.IsSampleFile`, in id order; anchor index k = position of the episode whose `id == anchor`, unset/unknown/non-episode → 0 — both in shared `pinEpisodes` (`:65-77`, called `:151`). Subtitles, audio, nfo, samples are not episodes.
4. Deleted = episodes `[0, k)`; live = every other file (non-episodes, episodes `>= k`) (`:152-168`).
5. `drop[p]` = p touched by a deleted episode **and** by no live file — a boundary piece shared with a live neighbour stays (`:169-171`).
6. Mode `all` **or no episodes** → `want[p] = !drop[p]` (`:173-178`).
7. Mode `next` → window = episodes `k .. min(k+N, len-1)`; `want[p]` = p touched by a window episode (`:180-190`). Non-episode files are not wanted by `next` (a boundary piece they share with a window episode is).

Layout adapter: `applyPin` (`server/torr/torrent.go:140-189`) under `muTorrent` — mode checked first (`:145`); not pinned or `!UseDisk` → `pinNoSpaceSet(hash, false)` + `cache.SetPin(nil, nil)` (`:146-151`); no `Torrent` or no info → `SetPin(nil, nil)`, no-space state kept (`:152-156`); else `pinFile{id: i+1, path, offset, length}` over `sortedFiles(t.Torrent.Files())` (`:158-161`) → `pinPieces(..., info.PieceLength, NumPieces(), PinMode, PinNext, PinAnchor)` (`:162`) → free-space check (below) → `SetPin`. Nil cache safe. `sortedFiles` (`pin.go:195-200`) is the same sort `Status()` uses (`torrent.go:434`), so ids match web/viewed ids.

## Flow — pin set in storage
1. **`SetPin(want, drop)`** (`server/torr/storage/torrstor/cache.go:131-170`): nil-safe; under `muRemove` compare with the current set (`slices.Equal` on both, or both nil) — unchanged → return (`:141-147`); else store (`:148`), log `Set cache pin: <hash> pinned: <bool> wanted: <n> drop: <n>` (`:162`); if torrent attached and not closed → `go { clearPriority(); dropPieces() }` (`:163-169`).
2. **Download.** `clearPriority` raises wanted incomplete pieces to `Normal` (reader window priorities kept); not wanted pieces of a pinned torrent take the unpinned rule (`None` outside readers) (`cache.go:557-584`). `priorityWatchdog` re-arms every 5 s while `pin != nil` even without readers (`cache.go:119`).
3. **Keep.** Every piece of a pinned torrent is exempt from eviction — not candidates, not in `c.filled`, `removePiece` refuses (`isKept`, `cache.go:405-407`, `:298`). Data outside the window survives; only `dropPieces`, `rem` and `off` delete.
4. **Stay loaded.** `expired()` false while `cache.PinPending()` (`server/torr/torrent.go:296`) = any wanted piece not `Complete` (`cache.go:173-183`). All wanted complete (or paused) → normal timeout.
5. **Unpin.** `SetPin(nil, nil)` → async `clearPriority` lowers pieces to `None` outside readers; `dropPieces` returns immediately (unpinned); nothing deleted in the cache. Dir deletion: data lifecycle flow.

Details of eviction/priority/drop internals: [Torrent storage cache](torrent-storage-cache.md#pin-api-cachego).

## Flow — anchor trigger and watched cleanup
1. **Hook.** `Torrent.Stream` calls `updatePinAnchor` after the file is resolved and passes the `MaxSize` check, before `t.NewReader` (`server/torr/stream.go:83`).
2. **Conditions** (`server/torr/pin.go:209-226`): return false unless `method == GET`, not `?probe=1`, `Stat != TorrentPreload`, `!settings.ReadOnly`, path is an episode (`:210-213`); under `muTorrent` false unless mode `all`/`next` and `PinAnchor != fileID` (`:214-218`). Then set the mirror (`:219`), log `Set pin anchor: <hash> <id>` (`:223`), `go t.savePinAnchor(hash)` with `hash` read before the goroutine (`:222-224`), return true. Stream continues immediately.
3. **Persist** `savePinAnchor` (`:229-245`): loop { read mirror anchor under `muTorrent`; `settings.SetTorrentPinAnchor` **outside** the lock; re-lock, break when mirror still equals the written anchor } (`:232-243`); then `applyPin()` (`:244`).
4. **Recompute.** New anchor → new `drop` (episodes before K) and, for `next`, new window → `SetPin` change → async `clearPriority` + `dropPieces`.
5. **Drop** `dropPieces` (`cache.go:199-233`): closed / no torrent / unpinned → return (`:200-202`). Protected = whole piece range of the file of every registered reader, snapshotted once (`:206-215`). Per piece: `muRemove.Lock`, reload current set, `p.Release()` when not closed, `drop[id] && !want[id]`, not protected and `Size > 0 || Complete` (`:221-228`). Log `Drop pinned pieces: <hash> <count>` when count > 0 (`:230-232`). `Release` removes the file, `Size=0`, `Complete=false`, anacrolix priority `None` + `UpdateCompletion`. A dropped file stops being complete → its id leaves `PinDownloaded` on the next `progressEvent`.
6. **Probes** never move the anchor: `/ffp/:hash/:id` (`server/web/api/ffprobe.go:62`) and tgbot `/ffp` (`server/tgbot/ffp.go:54`) append `?` + `torr.ProbeQuery` + `=1`; preload's own probe (`server/torr/preload.go:107-112`) runs while `Stat == TorrentPreload`. `HEAD` requests do not move it.
7. **Backward jump** to episode j: j becomes the anchor → window j..j+N re-pinned, only episodes before j dropped.

**Mode / N change:** `SetTorrentPin` → `applyPin` recomputes from the stored anchor; `SetPin` re-runs the drop (idempotent, depends only on K); data outside the new window is kept (`isKept`).

## Flow — download set / status fields (Phase 5)
1. **Targets** `pinTargets(files, mode, next, anchor)` (`server/torr/pin.go:83-106`): nil unless `all`/`next` (`:84-86`); same `pinEpisodes` rule as `pinPieces`; `next` with episodes → episodes `k..min(k+N, last)` (`:89-98`); `all` or no episodes → every file except episodes before k (`:99-105`). Invariant: `pinPieces.want` == union of piece ranges of target files with `length > 0` (`TestPinTargetsMatchPinPieces`).
2. **Loaded with info** (`server/torr/torrent.go:434-454`), only when mirror mode `all`/`next` (`:396`): `pinFile`s built in the same `sortedFiles` pass as `FileStats` (`:436-445`); per file `Pinned = targets[i]`, `Completed = fileCompleted(f)` (Σ `Bytes` of `File.State()` entries with `Complete`, `pin.go:249-257`), `Downloaded = id ∈ mirror PinDownloaded` (`:447-452`); `PinProgress = pinProgress(..., Completed)` (`:453`).
3. **DB stub** (`t.Torrent == nil`, `:474-495`): `dataFiles(t.Data)` (`pin.go:261-274`: unmarshal `tsFiles`, keep `Id > 0`, sort by id; error / no TorrServer list → nil). Empty → no `file_stats`, no progress. Else one `TorrentFileStat{Id, Path, Length, Pinned, Downloaded}` per file (no `Completed`); progress done = `length` of downloaded targets (`:488-493`).
4. **Loaded without info:** unchanged (no `file_stats`, no progress).
5. **Progress** `pinProgress` (`pin.go:110-122`): `int(100 × Σ done / Σ length)` over targets with `length > 0`, int64 floor; total 0 → 0 (omitted).
6. **Error** (`torrent.go:496-499`): `pinned && PinProgress < 100 && pinNoSpaceHas(hash) && UseDisk` → `PinError = "no_space"`, loaded or stub. `hash` = spec hash, overwritten by `Torrent.InfoHash()` (`:397-406`).
7. **Unpinned:** one mode check, none of the fields set (all `omitempty`) → JSON byte-identical (`TestStatusUnpinnedHasNoPinProgress`, `TestListExposesPin`).

## Flow — downloaded ids (Phase 5)
1. **Trigger** `progressEvent` calls `t.updatePinDownloaded()` first, before `expired()` (`server/torr/torrent.go:237-239`), so the final completion is recorded before a timeout unload.
2. **Compute** `updatePinDownloaded` (`server/torr/pin.go:306-332`): return if `ReadOnly` or `!UseDisk` (`:307-309`); under `muTorrent` return unless mode `all`/`next`, `t.Torrent != nil`, info (`:310-315`); `ids` = ascending ids (`sortedFiles`, `i+1`) of files with `Length() > 0 && fileCompleted == Length()`, nil when none (`:316-321`); `slices.Equal(ids, mirror)` → return (`:322-325`); set mirror, read hash, unlock (`:326-328`); log `Pin downloaded files: <hash> <ids>` (`:330`); `savePinDownloaded(hash)` (`:331`).
3. **Persist** `savePinDownloaded` (`:335-350`): loop { clone mirror under `muTorrent`; `settings.SetTorrentPinDownloaded` outside the lock; break when mirror still equals the written ids } — same shape as `savePinAnchor`.
4. **Setter guard** `SetTorrentPinDownloaded` (`server/settings/torrent.go:106-123`): missing row or `PinMode == ""` → false, nothing written (`:112-114`). Invariant: unpinned row ⇒ no downloaded ids.
5. **Removal:** drop by the anchor rule makes a file incomplete → removed next tick; `off` clears row (`settings/torrent.go:74-76`) and mirror (`apihelper.go:214-216`); `rem` deletes the row.
6. **`AddTorrentDB`** builds `Data` from `Status().FileStats` copying only `Id`/`Path`/`Length` (`server/torr/dbwrapper.go:26-29`), so live `pinned`/`completed`/`downloaded` never land in `Data`. No-op for unpinned (fields were empty).

## Flow — free space and pause (Phase 5)
1. **Probe** `utils.FreeSpace(path)` — see Key files. `torr.freeSpace` (`server/torr/pin.go:26`) is the test seam. Unknown (`ok=false`) never pauses.
2. **Check in `applyPin`** (`server/torr/torrent.go:164-188`), pinned + `UseDisk` + info: `required` = Σ `info.Piece(i).Length()` over `want[i] && !PieceState(i).Complete` (`:166-171`); `free, ok := freeSpace(settings.BTsets.TorrentsSavePath)`; `paused = ok && required > 0 && free < required + pinFreeSpaceMargin` (`:172-173`).
3. **Record** `pinNoSpaceSet(hash, paused)`; on change log `Pin paused, no space: <hash> <free> <required>` or `Pin resumed, space available: <hash> <free> <required>` (`:174-181`).
4. **Push** paused → `SetPin(make([]bool, len(want)), drop)` (`:182-186`); else `SetPin(want, drop)` (`:188`).
5. **Paused cache** (no torrstor change): `clearPriority`/watchdog/`CloseReader` keep every non-reader piece `None`; reader priorities unchanged; `isKept` (non-nil) still blocks eviction; `dropPieces` still releases `drop`; `PinPending` false → expires normally (`TestPausedPinSetRaisesNothing`, [Torrent storage cache](torrent-storage-cache.md)).
6. **Recheck** every resume tick: `resumePinned` calls `applyPin` on loaded torrents whose mirror mode is `all`/`next` (`server/torr/resume.go:47-54`); an unloaded paused pin is unfinished, so the tick loads it and `WaitInfo` → `applyPin` rechecks. Recovery → `SetPin(want, drop)` → priorities re-armed, `PinPending` keeps it loaded.
7. **Clear** the entry: non-paused check; `applyPin` with mode off or `!UseDisk` (`torrent.go:146-151`); `off` (`apihelper.go:198-200`); `rem` (`apihelper.go:276`). Kept while the torrent has no info (`torrent.go:152-156`).

## Flow — data lifecycle (Phase 3, C2 in Phase 4)
**Delete paths** (only these delete a pinned torrent's data):
1. **`off`, not loaded, row existed pinned** → `removeTorrentDir` synchronously (`server/torr/apihelper.go:205-207`).
2. **`off`, loaded, row or mirror pinned before** → `removeTorrentDirAfterClose` goroutine (`:246-268`): waits `<-torr.closed` (`:247`); `muTorrent` lock/unlock barrier (held by `drop()` while anacrolix closes the storage) and reads the mirror — `PinMode != ""` → keep (`:250-255`); `torr.bt.GetTorrent(hash)` is a different non-nil `*Torrent` → keep (loaded again, `:258-262`); `sets.IsTorrentPinned(hash)` → keep (`:263-265`); else log `Removing cache files for:` + `os.RemoveAll(name)` (`:266-267`). Reads neither global `bts` nor `sets.BTsets`. The stream is never interrupted: the dir goes when the torrent unloads by timeout/drop/rem.
3. **`rem`** (`RemTorrent`, `:270-307`): `pinNoSpaceSet(hash, false)` first (`:276`); not loaded → `RemTorrentDB` then `removeTorrentDir` (`:280-285`); loaded → `RemTorrentDB` **before** `bts.RemoveTorrent` (`:291`, `:294`), wait `closed` or 5 s, `removeTorrentDir` (`:305`). Details: [Torrent API helpers](torrent-api-helpers.md).
4. **Anchor drop** (piece files only, dir stays): `dropPieces` above.
5. `removeTorrentDir` (`:234-242`): `UseDisk && hashHex != "" && hashHex != "/"` → stat `TorrentsSavePath/<hash>`, log `Removing cache files for:`, `os.RemoveAll`.

**Keep paths** (pinned = row `PinMode != ""`):
- `Cache.Close` with `RemoveCacheOnDrop`: `settings.IsTorrentPinned(c.hash)` → log `Keep pinned cache on close:` and skip deletion (`server/torr/storage/torrstor/cache.go:269-271`). Covers `DropTorrent`, timeout unload, `dropAllTorrent`, `Disconnect`.
- Startup `cleanCache` with `RemoveCacheOnDrop`: pinned hash set from `settings.ListTorrent()` (`server/server.go:96-102`); matching dir → log `Keep pinned cache:` + skip (`:127-130`). Without `RemoveCacheOnDrop` every DB torrent's dir is kept (unchanged, `:112-125`).
- `drop`/timeout/`dropAllTorrent` have no deletion code of their own.

**Resume** (`server/torr/resume.go`):
1. `pinnedToResume` (`:23-34`): `bts == nil` or `!UseDisk` → nil; else `ListTorrent` rows with `PinMode` `all` **or `next`**, `!pinFinished(db)` and `bts.GetTorrent(hash) == nil` (`:29`), `ListTorrent` order.
2. `pinFinished(db)` (`server/torr/pin.go:279-302`): mode `all`/`next` (`:280-282`); `targets = pinTargets(dataFiles(db.Data), ...)`; every target with `length > 0` in `db.PinDownloaded`, at least one such target (`:283-294`); spec present and `TorrentsSavePath/<hash>` exists (`:295-301`). Mode/N (DB setter) or anchor change → new targets → next tick reloads.
3. `resumePinned` (`:38-55`): per hash log `Resume pinned torrent:` + `GetTorrent(hex)` (non-blocking DB copy + async `NewTorrent`/`copyPin`/`GotInfo`, `server/torr/apihelper.go:119-135`) (`:39-43`); then, `bts != nil`, for each `bts.ListTorrents()` entry read mirror mode under `muTorrent` and call `applyPin()` when `all`/`next` (`:44-54`) — free-space recheck. Loaded torrents never reach `GetTorrent`, so their expiry is not extended.
4. `StartResumePinned` (`:59-82`): under `resumeMu`, no-op if running; goroutine runs `resumePinned()` immediately, then on a 1-minute `time.Ticker` until `stop`; `defer close(done)`. `StopResumePinned` (`:85-94`): close `stop`, wait `done`, nil both. Both idempotent; Start after Stop runs a new loop (embedded restart).
5. Wiring: startup = `web.Start` → `BTS.Connect()` → `torr.StartResumePinned()` (`server/web/server.go:59-64`); `web.Stop` → `StopResumePinned()` before `BTS.Disconnect()` (`:168-169`); settings reload → `resumePinned()` right after `bts.Connect()` (`server/torr/apihelper.go:353-354`, `:372-373`).

## Gotchas / decisions
- **DB row owns the pin.** `settings.AddTorrent` copies all four pin fields from the stored row when one exists (`server/settings/torrent.go:50-55`); the caller's pin is used only for a new row. Every general save (`AddTorrentDB`, `SetTorrent`, `SaveTorrentToDB`, migration) therefore cannot change a pin. Pin/anchor/downloaded change only through dedicated per-row setters under `settings.mu` (`SetTorrentPin`, `SetTorrentPinAnchor`, `SetTorrentPinDownloaded`), never `AddTorrentDB`.
- **In-memory pin is a mirror** guarded by `muTorrent`: written by `copyPin` (dst lock, `PinDownloaded` cloned, `server/torr/apihelper.go:92-100`), `SetTorrentPin` (`:210-217`), `updatePinAnchor` (`server/torr/pin.go:219`) and `updatePinDownloaded` (`pin.go:326`); read by `AddTorrentDB` (`server/torr/dbwrapper.go:49-54`), `applyPin` (`server/torr/torrent.go:143-188`), `savePinAnchor` (`pin.go:233-239`), `savePinDownloaded` (`pin.go:339-345`), `resumePinned` (`server/torr/resume.go:48-50`) and `removeTorrentDirAfterClose` (`server/torr/apihelper.go:250-252`). `Status()` reads it under its own `muTorrent` hold.
- **`Cache.pin` is a copy computed from the mirror**, pushed by `torr` whenever pin, anchor, cache or free space changes. Not derivable inside `torrstor`: it cannot import `torr` (cycle), and eviction/priority paths are hot and lock-free. Phase 4 new mutable state: only `pin atomic.Pointer[pinSet]`. Phase 5 new mutable state: only the `torr` no-space set; `PinDownloaded` became live; no new `Torrent`/`TorrentDB`/`BTSets`/`Cache` fields, no torrstor code change.
- **`UseDisk` gate lives in `applyPin`**, read at apply time (`server/torr/torrent.go:146`). A memory-mode pin would grow RAM without bound; the API already rejects it, this covers `UseDisk` switched off later (settings reload recreates caches and re-runs `WaitInfo`).
- **`applyPin` checks the mode first (5e):** an unpinned disk torrent builds no layout on every `WaitInfo`/`copyPin` (result was already `SetPin(nil, nil)`); it also clears the no-space entry there.
- **`applyPin` pushes under `muTorrent`** so a stale apply cannot overwrite a newer one. `SetPin` takes only `muRemove` and spawns a goroutine; lock order `muTorrent` → `muRemove` → `muPrio`/anacrolix lock; `dropPieces` never takes `muTorrent`. The no-space mutex is a leaf. DB writes (`savePinAnchor`, `savePinDownloaded`) never under `muTorrent`. A `pin` request, `WaitInfo` or anchor save that changes the set may wait one eviction pass or one piece release.
- **`expired()` gate is cache-derived** (`PinPending`), no `Torrent` field; "unfinished" = at least one wanted piece not `Complete`. `next` with a complete window times out normally even though later episodes are missing.
- **Keep-beyond-window = no eviction for a pinned torrent at all** (curator-delegated, chosen over "window ∪ completed pieces at recompute time"): one predicate (`pin != nil`), no snapshot state, same as Phase 2 `all`. Cost: data a player streams from a non-episode file (external audio, subtitles) or a preload of a non-anchor episode stays on disk until `dropPieces` (only if before K), `off` or `rem`.
- **Backward jump re-pins the new window** (interpretation of mission "a deleted episode played again streams via the normal cache and is not re-pinned"): starting an episode always makes it the anchor, so it is in the window by definition. With `all`, a jump back to j re-downloads deleted episodes `>= j` — data the user no longer has, so "do not re-download data the user already has" holds.
- **No episodes → `next` pins like `all`** (no drop): the global default mode is `next`; a pin downloading nothing on an audiobook/soft torrent would be a silent no-op (`TestCopyPinAppliesPinToLoaded`). Same rule in `pinTargets`.
- **Unset / stale anchor → first episode.** An anchor on a non-episode id (cannot be produced by the trigger) is treated as unset.
- **Anchor moves only while pinned** (curator trigger rule). Watching while unpinned leaves the anchor stale; a later pin uses it. `off` keeps the anchor.
- **ReadOnly → no anchor move** (no DB write, no data deleted by a read-only instance), consistent with `SetTorrentPin` rejecting ReadOnly. ReadOnly also skips downloaded-ids maintenance; status shows the stored ids.
- **Drop runs on every pin-set change**, not only on anchor change (load after restart, mode/N change, anchor change). Drop depends only on K, so re-running is idempotent and also removes pieces a reader protected at the previous run.
- **Drop never touches a file that has a reader (amended after 5e):** every piece of a file with a registered reader stays until the next pin-set change, not only its reader window. A reader advancing or seeking during the pass, or a second viewer on an earlier episode, would otherwise lose data it is about to read. A write anacrolix already had in flight for a dropped piece may recreate a partial file (priority `None`, not continued); it stays until the next drop.
- **Non-episode files before K are never deleted** and stay wanted (and targets) in `all`.
- **`muRemove` per piece in `dropPieces`** so `applyPin` (under `muTorrent`, which `Status()` and therefore `Stream` need) never waits for a whole drop pass; the set is re-loaded per piece so only the current set drops.
- **Loopback probes do not move the anchor (spec-first after 5a):** `/ffp/:hash/:id` and tgbot `/ffp` GET `/play/<hash>/<id>` while `Stat` is Working; an ffprobe of a later episode would have dropped every episode before it. They append `?probe=1` (`torr.ProbeQuery`). The tgbot edit is a one-line guard, not a tgbot feature. **Known limitation:** third-party metadata scanners that GET `/play` URLs still move the anchor (curator GET rule stands).
- **Anchor DB write outside `muTorrent` (5a):** measured 9.4 ms avg / 15.9 ms max per `SetTorrentPinAnchor` on SSD (real bbolt); holding `muTorrent` across it stalled `Status()` of concurrent streams. The write-then-recheck loop keeps the newest anchor last.
- **`updatePinAnchor` returns whether a save was scheduled** — synchronous seam for negative tests (5a: the same-file check was untested).
- **C1 fixed at the size fallback only:** `AddTorrentDB` uses nil-safe `torr.Length()` (0 without info) (`server/torr/dbwrapper.go:43-44`); `Status().FileStats` was already nil-safe. Pin on a loaded torrent without metadata and without row → row created with the pin and `Size 0`, no panic.
- **C2: `off` deletes only if pinned before** — "pinned before" = DB row pinned (`IsTorrentPinned` before the write, `server/torr/apihelper.go:196`) or loaded mirror pinned (read under `muTorrent` before the mirror update, `:211`). `off` on an unpinned torrent is a pure DB/mirror no-op. Replaces the Phase 3 "`off` = unpin and delete data" spec-challenge decision. Unknown hash (no row, not loaded) → nothing deleted.
- **`off` on a loaded torrent deletes after close**, not immediately and not by force-unloading (curator): a loaded `DiskPiece.WriteAt` opens with `O_CREATE` but never recreates the dir (`server/torr/storage/torrstor/diskpiece.go:38`), so deleting under a live cache breaks downloads/streams; force-unloading would cut playback. The dir disappears when the torrent unloads (≈1 s after `off` when idle and past expiry, else after the stream ends + `TorrentDisconnectTimeout`). Path and hash are computed at request time: `Torrent.Hash()` reads `t.Torrent` unsynchronised against `drop()`.
- **Deferred delete re-checks** mirror (`muTorrent`), identity and DB row right before `RemoveAll`. Identity, not nil: `drop()` (settings reload `dropAllTorrent`) and `client.Close` leave the closed `*Torrent` in `bt.torrents`, so "loaded again" = a different `*Torrent` under the hash (`TestSetTorrentPinOffLoadedRemovesDirAfterDropAll`). Mirror check: `off` → re-pin → embedded `server.Stop` closes the DB, where `IsTorrentPinned` reads nil (`server/settings/dbreadcache.go:34`) and would delete a re-pinned dir. A re-pin after close during shutdown is not covered. Window between checks and `RemoveAll` accepted — `RemTorrent` has the same.
- **`muTorrent` barrier in `removeTorrentDirAfterClose` has no failing test without it** (test path closes synchronously); reasoning evidence only.
- **`UseDisk=false` → no deletion** on `off`/`rem` (curator). Data written while `UseDisk` was on stays.
- **`RemTorrent` loaded branch deletes the row first** (Phase 3 5a): a resume tick between `RemoveTorrent` and a later row delete could reload a removed pinned torrent. Residual window: a tick that copied the row just before the delete. Ordering only, no unit test. Side effect: `Cache.Close` with `RemoveCacheOnDrop` sees no row and deletes files too (final state unchanged).
- **Resume `all` and `next`** (`pinnedToResume`, the modes `applyPin` pins).
- **Finished pins are not reloaded (Phase 5, replaces Phase 4 "finished pins churn"):** `pinnedToResume` skips rows where `pinFinished` — every target with `length > 0` is in `PinDownloaded`, `Data` has a TorrServer file list and `TorrentsSavePath/<hash>` exists. Only targets count; a non-target missing file does not keep the pin unfinished.
- **Resume tick re-applies loaded pins (Phase 5):** `resumePinned` calls `applyPin` for every loaded torrent with mirror mode `all`/`next`, even with an unchanged set (curator: cost one `statfs` + a piece-state pass per pinned torrent per minute; `SetPin` suppresses unchanged sets).
- **`pinned` = target file, not piece overlap** (curator-delegated; curator suggested overlap): overlap would mark subtitles sharing a boundary piece as pinned forever and block "finished".
- **`PinDownloaded` = every complete file of a pinned torrent**, derived each second, written on change (curator-delegated). No separate "clear on drop" path: a dropped file stops being complete. Resume "finished" looks only at targets.
- **`pin_progress` bytes-based over target files**; stubs use downloaded target lengths (lower bound, partial files count 0). Absent with `pin_mode` present = 0.
- **Stubs report `pinned` and `downloaded` from `Data` + row, no `completed`.** `Data` without a TorrServer file list → no per-file state and no progress (the layout is unknown without metadata).
- **`AddTorrentDB` strips pin fields from `Data`** (`server/torr/dbwrapper.go:26-29`): `Data` is built from `Status().FileStats`, which now carries live `completed`/`downloaded`; persisting them would bake stale values into a client-visible field.
- **Paused pin may expire** (curator): empty want set → `PinPending` false; the resume tick loads it again each minute and rechecks. Cost: one load (metadata from peers for magnets) per minute per paused pin.
- **No-space state is an in-memory per-hash set in `torr`**, not a DB field and not cache state: a paused pin alternates between loaded and stub, and the error must stay visible on the stub (`TestPausedStubKeepsPinError`); lost on restart, restored by the first resume load (seconds).
- **Margin: fixed 1 GiB** (`pinFreeSpaceMargin`, `server/torr/pin.go:23`). Keeps room for the settings DB, logs, the OS and the streaming cache of unpinned torrents; a percentage would be too large on big disks and too small on small ones.
- **`required` counts the full length of every wanted incomplete piece** (partially written pieces counted fully — conservative, no per-piece size reads).
- **Per-torrent check, no global budget:** two pins checked independently can together exceed the free space between two ticks; the next tick pauses. Known limitation (mission: no concurrency limit).
- **`all` pauses all-or-nothing** (accepted 5a): no partial window that would fit.
- **Live pin status ignores `UseDisk`** except `pin_error`; with `UseDisk` off the pin is inert and progress stays as last seen on disk.
- **`SetTorrentPinDownloaded` writes only a pinned row (spec-first after 5a, finding 1):** a downloaded save landing between `off`'s row write and its mirror clear left old ids on an unpinned row; a later DB-only re-pin then reported the pin finished with no data on disk and the resume loop never loaded it. Setter refuses `PinMode == ""` under `settings.mu` (`server/settings/torrent.go:112-114`, `TestSetTorrentPinDownloadedUnpinnedRow`).
- **`pin_error` only while `pin_progress < 100` (spec-first after 5a, finding 2):** a paused pin finished by streaming unloads by timeout, is skipped as finished and never re-applied, so its stub kept `no_space` until restart/off/rem. A finished pin needs no space (`server/torr/torrent.go:497`).
- **Finished requires the data dir in the current save path (spec-first after 5e Codex, finding 1):** `SetSettings` can change `TorrentsSavePath`; a finished pin would keep its ids and never load from the new, empty path. `pinFinished` stats `TorrentsSavePath/<hash>` (`server/torr/pin.go:300-301`); once loaded, `updatePinDownloaded` recomputes the ids from the new storage (live smoke step 4). Partial external deletion inside the dir is not detected (same trust as `diskpiece.go`).
- **Accepted (5a, downgraded):** `RemTorrent` clears the no-space entry before the up-to-5 s close wait — a resume tick in that window can re-add it (a re-added and re-pinned hash shows `no_space` until its first `applyPin` after info); `statfs` runs under `muTorrent` (a hung network save path blocks that torrent's `Status()` — piece writes hang there anyway); a paused pin still grows the disk through streaming (eviction protection applies while paused); rows with client-owned `Data` (no TorrServer file list, e.g. Lampa) are never finished and keep the per-minute reload; redundant no-space clear in loaded `SetTorrentPin` (M48) kept for symmetry with the DB-only branch.
- **Accepted (5e Codex, finding 2, downgraded):** a client replacing `Data` via `set` with a truncated or renumbered TorrServer file list can make `pinFinished` true for an unfinished pin. Validating against `Size` is unreliable (client-supplied).
- **Stalled pins** (no peers) stay loaded forever — Phase 2 rule, mission "keep loaded until downloaded"; no stall timeout.
- **Concurrent resume** (ticker + settings reload, two ticks before `NewTorrent` registers): `NewTorrent` dedups by hash in `bt.torrents` and anacrolix `AddTorrentSpec`; a second `copyPin`/`GotInfo` is a no-op in effect. Accepted.
- **Settings-reload window:** a tick between `dropAllTorrent` and `Disconnect` may load into the old client; `Disconnect` closes it and `resumePinned` after `Connect` loads it again. A tick while `client == nil` fails in `NewTorrent` silently and retries next minute.
- **`GotInfo` reads `TorrentDisconnectTimeout` before `WaitInfo`** (`server/torr/torrent.go:201-203`): otherwise the async load's last action read `settings.BTsets` after every synchronised point and raced the test fixture restore. Production effect: expiry extension uses the value from the start of the info wait.
- **Accepted, not fixed (Phase 4 5a):** `dropPieces` snapshots reader files once per pass — a reader created during the pass (window ≈ DB write + recompute) is not protected (best effort); `Release` racing an in-flight anacrolix hash check can leave `Complete=true` without a file (same as the pre-existing `removePiece` path); unlocked `Piece.Size/Complete` reads in `dropPieces` (pre-existing pattern in `GetState`/`PinPending`); watchdog `pin != nil` condition and `SetPin` nil→nil branch have no unit test; a zero-length episode takes a window slot; `sortedFiles` sorts anacrolix's internal file slice in place (pre-existing in `Status()`); `utils.CompareStrings` is not transitive for `E1`/`E2`/`E10` (pre-existing, affects file ids everywhere).
- **Accepted (Phase 4 5e, downgraded):** an anchor save goroutine of a torrent instance dropped and reloaded while suspended between reading the mirror and the ~10 ms DB write can overwrite the newer instance's anchor (needs full unload + reload inside that window; next anchor move corrects it). The C2 "unpinned loaded off keeps dir" test uses a control torrent as a practical, not formal, ordering barrier (mutation caught 20/20 runs); no synchronous seam added.
- **Accepted races (Phase 3 5a/5e):** a tick's pin snapshot vs `off`/`rem` on a DB-only torrent within the ms before `NewTorrent` registers (can start a background download; no cheap fix); load goroutines started by a tick are not joined by `StopResumePinned` (same as HTTP `GetTorrent`); startup `cleanCache` snapshot vs a pin made during the first seconds of cleanup with `RemoveCacheOnDrop`.
- **No unit test for call sites** `web.Start`/`web.Stop`/`SetSettings`/`SetDefSettings` (real `Connect` opens listeners, sleeps 2 s) and `Stream` → `updatePinAnchor` (a GET needs peers/data); live smoke is the evidence.
- **`cState.Filled` / `PreloadedBytes` include pinned bytes**; only the eviction counter `c.filled` excludes them. Remaining torrstor-side decisions: [Torrent storage cache](torrent-storage-cache.md#gotchas--decisions).
- **Phase 4 step 5d skipped:** post-5e delta (whole-file reader protection, mode-first `applyPin`) ~15 production lines, both verified by mutation. **Phase 5 step 5d skipped:** fix delta (setter pinned-row guard, `pin_error` gate, `pinFinished` dir check) ~12 production lines, each caught by a mutation (F1–F3). Steps 1 and 3 folded into the orchestrator (Phases 0–4 precedent).
- `AddTorrent` copies the pin from the DB copy whenever a row exists (`server/torr/apihelper.go:84-86`) — DB wins over a stale mirror; no row → pin left as is.
- `off` is allowed with `UseDisk=false` so a pin never becomes un-removable after disk storage is disabled.
- `off` clears mode + N + `PinDownloaded` (row `server/settings/torrent.go:74-76`, mirror `server/torr/apihelper.go:214-216`) and the no-space entry; `PinAnchor` untouched. `next`/`all` keep `PinDownloaded`.
- Pinning a loaded torrent without a DB row persists it: `AddTorrentDB` runs the synchronous poster HTTP check (`server/torr/dbwrapper.go:39`) and, before metadata, stores `Data` as an empty file list (existing `save_to_db` behaviour). The second `SetTorrentPin` covers a concurrent ordinary save creating the row first.
- `pin_next` is stored for `all` too, so switching modes keeps N. Global default 0 is not expressible (`<=0 → 3`); per-pin N=0 is (window = anchor episode only).
- JSON `omitempty`: absent `pin_mode` = off; `pin_mode` set with absent `pin_next` = N 0; absent `pin_progress` = 0.
- Malformed hash panics in `metainfo.NewHashFromHex` (`server/torr/apihelper.go:193`) → gin recovery 500, empty body — same as `get`/`set`/`rem`.
- **Accepted race:** `GetTorrent`'s async load copies the pin from the DB copy captured before the goroutine (`server/torr/apihelper.go:119-132`); a pin or anchor written in that window leaves a stale mirror (wrong `Status()`, and wrong cache pin after `WaitInfo`) until the next `AddTorrent`/reload/`SetTorrentPin`/anchor move. It cannot reach the DB (row owns the pin).
